# 選択画像の推論・レビュー仕様

状態: ユーザー合意済み。実装済み。自動テストは外部依存欠如により一部未実行。手動動作確認待ち。

## 目的

大量画像の一括処理によるviewerの応答低下を避けるため、推論前に対象画像を選択し、選択画像だけを推論・レビューする。画像表示とYOLO/DINO修正保存の失敗も調査対象とする。

## 入出力

- 入力: 既存カタログの撮影日（`capture_date`）、撮影セッション、画像ID、既存の推論・レビュー状態、現在の推論設定。
- 出力: 選択画像の推論結果とレビュー画面、画像表示・保存の成否およびエラー。
- 撮影セッションDBを状態の正本とする。既存の公開契約、YOLO/DINOの保存・承認の独立性、監査記録を維持する。

## 動作

1. `run`開始時にSAM3モデル読み込みなど推論に必要な初期化を完了し、その後、推論開始前に対象選択viewerを開く。
2. viewerでは、既存カタログの`capture_date`を使って日付を選択する。選択した日付に該当するセッション候補に絞り、その中からセッションを選択する。日付の選択または変更に応じてセッション選択肢を更新し、選択中のセッションに属する画像IDを表示する。画像IDを複数選択し、選択完了後、選択された画像だけを推論処理へ渡す。未選択画像の推論・草案生成・レビュー状態は変更しない。
3. 推論完了後、従来どおりのアノテーション／レビュー画面を表示する。画面の対象は今回選択した画像とする。現在のrunフローでは、画像選択後にselection serverが終了し、レビューserverが別に起動する。
4. レビュー画面に「作業完了」操作を設ける。選択したセッションでの作業完了はユーザーがこのボタンを押した時とし、押下後は既存の画像選択画面`selection.html`へ戻す。DINO保存やYOLO公開を完了操作とみなさず、押下時にそれらを暗黙に実行しない。選択画面とレビュー画面には既存のHTMLを使い、新しいHTMLページは作らない。
5. 対象選択viewerとレビュー画面は、どちらも50件ずつページ送りできる。
6. 既に推論済み・レビュー済みの画像も選択可能とし、初期状態から除外しない。既存の処理状態を選択画面で識別できるようにする。YOLOとDINOの状態は独立して表示する。DINO状態は永続化された判定・承認状態を反映し、maskファイルの存在だけを判定済みの根拠にしない（mask存在は上書き確認用の情報）。
7. 画像表示またはYOLO/DINO保存で失敗した場合、エラーを明示する。失敗を保存成功として扱わず、未保存の編集内容を失わない。
8. 1000画像規模での選択・レビュー操作を検証し、変更前後の負荷・所要時間を報告する。数値の速度目標は本仕様では定めない。

## 制約

- 未選択画像の予測結果、草案、レビュー・承認状態、公開成果物を変更しない。
- 既存のレビュー、承認、公開の動作と外部契約を維持する。
- 作業完了から画像選択画面への復帰は既存の`selection.html`を再利用し、具体的な遷移方式は定めない。既存API/DB契約の変更を前提としない。
- 画面表示・通信・選択状態の実装方法は本仕様では決めない。
- 日付選択には既存カタログの`capture_date`を使用し、新しいDB項目やAPI契約は追加しない。

## 受け入れ条件

| 状況 | 期待結果 |
|---|---|
| `run`起動 | SAM3の必要な初期化後、推論より先に対象選択viewerが開く |
| 日付・セッション・画像ID選択 | 既存カタログの`capture_date`から日付を選ぶと該当するセッション候補に絞られ、セッション選択肢が更新される。セッションを選ぶとそのセッションに属する画像IDが表示され、選択画像だけが推論処理へ渡る。未選択画像の状態は変わらない |
| 推論済み・レビュー済み画像 | 初期状態で除外されず選択でき、既存状態を識別できる |
| DINO状態の一覧表示 | 永続化された判定・承認状態を正確に示し、maskファイルの存在だけで判定済みにしない。YOLO状態は独立して表示し、変更しない |
| 50件を超える一覧 | 50件ずつページ移動でき、ページをまたいだ選択状態が維持される |
| 推論完了 | 選択画像の通常レビュー画面が表示され、既存のレビュー・公開動作を維持する |
| レビュー作業完了 | ユーザーが「作業完了」を押すと既存の`selection.html`へ戻る。DINO保存・YOLO公開は暗黙に実行されず、新しいHTMLページは作られない |
| 画像表示または保存失敗 | エラーを表示し、失敗を成功扱いせず、未保存の編集内容を保護する |
| 1000画像規模 | 選択とレビューの操作を確認し、変更前後の計測結果を報告する。速度の数値閾値は設けない |

## 決定事項

- 選択した画像に同一推論設定のキャッシュがある場合は現行どおり再利用し、強制再推論は追加しない。既存承認を破壊的に更新しない。

## 残る確認事項

- 性能の数値目標・許容閾値は未決。1000画像規模の実データまたは実環境に即した計測結果を基に決定する。
