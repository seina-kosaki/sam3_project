# 解析機能仕様

状態: ユーザー合意済み・仕様確定。成功率と器具あたり過検出数を算出する。

## 目的

正解bbox・maskがないため、撮影器具単位でYOLO側のbbox確認とDINO側のmask採否を使い、物体検出とセグメンテーションを独立に評価する。外部の正解データに対する精度評価ではなく、レビュー結果と人手修正の状況を集計する。

## 入出力

- 入力: `src/configs/capture.json`の`capture_root`にある日付・セッション別の撮影データと、既存の推論結果・レビュー結果。解析範囲と解析設定は`src/configs/analyze.yaml`で指定する。
- 実行: `python src/analyze.py`。HTTP APIは設けず、実行時の対象・設定は設定ファイルから読み込む。
- 出力: `src/configs/analyze.yaml`の`output_root`（既定値`results_analyze`）配下に`run_NNNN/`を作り、日本語の全体サマリと器具種別ごとの解析結果を保存する。相対パスは`pyproject.toml`があるプロジェクトルート基準で解決し、symlink解決後も同ルート配下に限定する。`NNNN`は`0001`から始まる連番とし、実行ごとに新しいディレクトリを作る。表はCSVと画像、グラフはPNGで保存する。実行に使った`analyze.yaml`も同じディレクトリに保存する。表画像が長く一覧性を損なう場合は複数画像に分割する。失敗例画像は器具別・評価区分別に保存する。
- 解析は既存データを読み取って集計し、撮影データやレビュー結果を変更しない。

## 対象範囲

`analyze.yaml`には解析対象条件を複数指定できる。各条件には日付を必須とし、セッション指定は次のいずれかを任意で使う。

| 条件 | 対象 |
|---|---|
| 日付のみ | 指定日付配下にあるすべてのセッション |
| 日付と`session_id` | 指定日付配下の該当1セッションのみ。既存形式として維持する |
| 日付と`session_ids` | 指定日付配下の配列に含まれるセッションのみ |
| `session_id`または`session_ids`のみ | 許可しない。日付の指定が必要 |

`session_ids`はセッションIDの配列で、配列は1件以上でなければならない。各セッションIDは英数字で始まり、英数字・`.`・`_`・`-`の80文字以内で指定する。同一target項目内で`session_id`と`session_ids`を併用してはならない。新旧形式は異なるtarget項目間で併用できる。

複数条件はORとして扱う。対象は条件に一致するセッションの和集合とし、条件が重複しても同じセッションを重複集計しない。対象条件を空にした場合に`capture_root`全体へ自動拡張しない。日付はディレクトリ構成に合わせて`YYYY-MM-DD`形式とする。

例：

```yaml
targets:
  - date: "2026-11-24"
    session_ids:
      - "session_001"
      - "session_002"
  - date: "2026-11-25"
    session_id: "session_003"
  - date: "2026-11-26"
```

この例では、最初の日付の2セッション、次の日付の1セッション、最後の日付の全セッションをORで対象にする。重複するセッションは一度だけ解析する。

日付は対象選択にのみ使い、日付ごとの集計は行わない。指定した全セッションをまとめて集計する。

## 評価方法

### 判定単位と指標

評価単位は画像ごとの撮影器具1個とする。同じ器具を10枚で撮影した場合は10単位であり、1画像に複数の撮影器具があれば器具ごとに数える。実装では現行撮影DBの`visible=True`タグを撮影器具単位として使い、`instrument_uid`と`instance_no`の組で画像内の器具を識別する。集計表示は`instrument_uid`ごとに行う。

| 分野 | 成功・失敗の判定 |
|---|---|
| 物体検出（bbox） | 撮影器具に正しく割り当てられ、YOLO確認後も初期推論bboxから人手で変更されていないbboxがあれば、その器具単位を成功とする。未検出、初期bboxの位置・サイズ修正、または採用bboxなしは失敗とする。人手追加bboxだけでは成功にしない |
| セグメンテーション（mask） | 撮影器具に正しく割り当てられ、DINO側で採用・承認されたmaskがあれば、その器具単位を成功とする。採用maskなし、rejected、またはpendingは失敗とする。mask編集機能は追加しない |

検出にYOLOを使用したかどうかは評価条件にしない。bboxの修正有無は、既存SQLに保存された初期推論bboxとYOLO承認済み注釈JSONを照合して判定する。mask画素の比較は行わず、DINOの採否状態で判定する。

YOLO未確認またはDINO pendingの器具単位も撮影器具数の分母に含め、該当するbboxまたはmaskの失敗として数える。未確認・pendingの器具数は別途表示する。解析対象はレビュー完了済みを想定するが、pending等が含まれていた場合に除外や算出不能にせず失敗として集計する。

撮影画像に可視器具タグがない場合は解析を中止する。物体記録にUIDがない場合、画像内の可視器具UIDが一意ならそのUIDへ対応付ける。複数UIDがあり一意に決められない場合は「器具未確定」行へ混ぜず、データ不整合として解析を中止する。

- 分母: 解析対象画像に写る撮影器具単位の総数。bbox・maskで同じ分母を使う
- bbox成功数: 初期推論のうち、撮影器具に正しく対応し、YOLO確認で変更されず採用されたbboxを持つ器具単位数
- mask成功数: DINOで採用されたmaskを持つ器具単位数
- bbox/mask失敗数: 分母から該当分野の成功数を引いた器具単位数
- bbox成功率、mask成功率: `成功器具数 / 撮影器具数`
- 未採用bbox数: 初期推論bboxのうち承認後に採用されなかった件数。人手修正・削除された初期推論bboxも1件として数える。人が新たに追加したbboxはモデル推論ではないため含めない
- 器具あたり平均未採用bbox数: `未採用bbox数 / 撮影器具数`。割合（%）ではなく、撮影器具1個あたりの平均個数とする

### 集計単位

- 全対象セッションをまとめた全体サマリ
- `instrument_uid`ごとの器具種別集計

器具の個体番号（`instance_no`）別集計および日付・セッション別集計は行わない。

### 表・グラフ

- 表には撮影器具数、bboxとmaskそれぞれの成功数・失敗数・成功率、YOLO未確認器具数、DINO pending器具数、未採用bbox数、器具あたり平均未採用bbox数を掲載する。
- 全体サマリ表と器具種別表を出力し、それぞれCSVおよび画像で保存する。
- グラフは全体および器具種別ごとのbbox・mask成功率と、器具あたり平均未採用bbox数を示す。日付別グラフは作成しない。
- 表とグラフ内の見出し・ラベルは日本語とする。
- 表画像は可読性を保てる長さで分割する。分割件数や画像サイズの数値基準は定めない。
- bbox・maskそれぞれの失敗例を、器具種別ごとに各3画像程度保存する。これは例示用の上限目安であり、集計はすべての失敗記録を対象とする。
- bbox失敗例の元画像には、初期推論bbox（修正前）とレビュー承認後のbbox（修正後）を異なる色で重ねる。画像内に日本語凡例を付け、修正前bboxと修正後bboxの色の意味を示す。
- 画像内には対象器具に関連するbboxを描画する。新規bboxは修正後bboxとしてのみ描画し、削除bboxは修正前bboxとしてのみ描画する。未承認候補は修正後bboxとして扱わない。
- bbox失敗例で対象画像に対象器具の検出結果がない場合は、bboxを描かず現行表示の「検出なし」を日本語で表示する。
- mask失敗例にはmaskを重ねる。対象画像で検出結果がない場合は、maskを描かず「検出なし」と日本語で表示する。
- 失敗例画像は元画像を含む解析結果として保存し、元の撮影画像・レビュー情報は変更しない。
- 失敗例は器具種別・bbox/mask別にランダムに選ぶ。該当する失敗例が3枚未満ならすべて保存し、0枚なら失敗例画像を出力しない。

#### 出力ファイル構成

```text
run_0001/
  analyze.yaml
  summary.csv
  instrument_summary.csv
  summary_table_01.png
  instrument_table_01.png
  success_rate_overall.png
  success_rate_by_instrument.png
  unaccepted_bbox_average_overall.png
  unaccepted_bbox_average_by_instrument.png
  failure_examples/
    bbox/<instrument_uid>/<date>_<session_id>_<image_id>.png
    mask/<instrument_uid>/<date>_<session_id>_<image_id>.png
```

画像表が複数枚になる場合は連番を増やす。該当失敗例がない区分には画像を出力しない。

## 制約

- 正解bbox・maskとの照合、適合率・再現率・F1・IoUの算出は対象外。
- 解析対象は設定で選択されたセッションに限り、未指定を全件解析として扱わない。
- 既存のYOLO確認とDINO物体採否・承認の独立性を維持する。
- 設定ファイルの場所は`src/configs/analyze.yaml`とする。

## 受け入れ条件

| 条件 | 期待結果 |
|---|---|
| `python src/analyze.py`を実行 | `src/configs/analyze.yaml`の設定で解析する。HTTP APIや実行引数を必要としない |
| 日付のみを指定 | その日付配下の全セッションを対象にする |
| 日付とsession IDを指定 | その日付の該当セッションだけを対象にする |
| 日付と`session_ids`を指定 | その日付の配列に含まれるセッションだけを対象にする |
| `session_ids`が空または配列でない | 不正な対象条件として扱い、解析を実行しない |
| 同一target項目に`session_id`と`session_ids`を併用 | 不正な対象条件として扱い、解析を実行しない |
| 異なるtarget項目で旧新形式を併用 | 両対象の和集合を一度ずつ解析する |
| session IDだけを指定 | 不正な対象条件として扱い、解析を実行しない |
| 複数の対象条件を指定 | 条件の和集合を一度ずつ解析する |
| 解析対象の撮影器具 | 可視タグ1件につき1単位として分母へ加える。1画像に複数器具があれば複数単位となる |
| 推論bboxが承認後に変更・削除された | 該当器具単位のbbox成功にはせず失敗にする。初期推論bboxを未採用bbox数へ1件加える |
| 人手でbboxを追加した | その器具単位のbbox成功にはしない。追加bbox自体は未採用推論bbox数へ含めない |
| 同一器具に推論bboxが複数ある | 正しく採用されたbbox以外の初期推論bboxを未採用bboxとして数える。1器具に3個の推論bboxがあり1個採用なら2個、3個とも失敗なら3個 |
| DINO pendingを含む解析 | pendingの器具単位も分母に含め、mask失敗として数え、別件数も表示する |
| DINO rejectedまたは採用maskなし | 該当器具単位をmask失敗として数える |
| 撮影画像に可視器具タグがない | 分母0の結果を作らず、不正な解析対象として中止する |
| 物体記録に器具UIDがない | 可視器具UIDが画像内で一意なら対応付ける。複数候補で曖昧なら器具未確定へ分類せず中止する |
| 解析完了 | 全体および器具種別ごとに撮影器具単位でbboxとmaskの成功率を集計し、過検出の平均個数も出力する。CSV表・表画像・PNGグラフ・失敗例画像・実行時設定YAMLを保存する。相対`output_root`はプロジェクトルート基準で解決し、プロジェクトルート外への出力を拒否する |
| 器具別の失敗例 | bboxとmaskそれぞれの失敗例から器具種別ごとにランダムに3枚程度保存する。3枚未満ならすべて、0枚なら画像を出力しない。検出結果がない画像は「検出なし」と表示する |
| bbox失敗例の重ね表示 | 同じ元画像に、初期推論bbox（修正前）とレビュー承認後bbox（修正後）を異なる色で重ね、画像内の日本語凡例で各色の意味を示す。対象器具に関連するbboxのみを描画する |
| bbox修正・追加・削除の可視化 | 新規bboxは修正後のみ、削除bboxは修正前のみ表示する。未承認候補を修正後bboxとして表示しない |
| 成功率と過検出 | 撮影器具数を分母にbbox・mask成功率を算出する。初期推論bboxの未採用数を撮影器具数で割った平均値を「器具あたり平均未採用bbox数」として表示し、割合（%）とは表記しない |
| 器具名 | `instrument_uid`を集計キーに保ち、master DBの`id`と完全一致する行の`name_ja`を表示名に使う。同名の別UIDは別集計のままUIDを併記し、対応行がない場合はUIDを表示する |
| 出力が長い | 表画像を分割して人が確認できる状態にする |
| 解析を実行 | 日付別の集計を作らず、元の撮影・レビュー情報を変更しない |

## 既存SQL記録の利用

- YOLO: 初期推論bboxは`sam3_prediction_objects.bbox_json`、承認後の注釈は`sam3_review_revisions.annotation_json`および`sam3_review_events.annotation_json`に記録される。`group_id`と物体番号を対応させ、bbox座標・追加・削除を照合することで、人手修正を判定できる。専用フラグやSQLスキーマの追加は不要。これは最終結果の差分判定であり、編集操作の担当者・時刻ごとの履歴を新たに記録するものではない。
- DINO: `sam3_object_reviews.dino_status`に`pending`／`accepted`／`rejected`があり、`sam3_object_review_events`に採否履歴が記録される。maskの成否は既存の採否で判定できるため、mask編集・修正履歴やschema変更は不要。accepted maskがない撮影器具単位は、rejected・pending・推論候補なしを含めてmask失敗とする。
- 現行DINOレビューはmask自体を変更せず、承認時に推論maskを正式保存する。従って、解析で使うmask失敗は人手編集ではなく、ユーザー合意に従い「採用されなかった」状態を指す。
- 器具名: `C:\work\SPD\master\dataset.sqlite`の`samples`から`id`と`name_ja`を読み、`instrument_uid == samples.id`で表示名を解決する。解析側はDBを読み取り専用で開く。DBがない、または必要なテーブル・列を読めない場合は解析を中止する。対応行がないUIDはそのまま表示し、同名の別UIDは別集計のままUIDを併記する。

## 未解決事項

なし。実装時は既存の`group_id`と物体番号で初期推論bboxと承認後注釈を対応付け、座標表現をそろえて差分を判定する。
