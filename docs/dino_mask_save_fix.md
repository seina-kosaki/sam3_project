# DINO mask保存バグ修正仕様

状態: 合意済み要件に基づく実装・回帰テスト追加済み（2026-11-04）。手動確認待ち。

関連する未実装の追加合意: [レビューUI改善仕様](review_ui_improvements.md)で「すべて不採用で保存して次へ」を追加する。この明示操作だけは全候補の個別選択・mask閲覧を必須としない。全候補の不採用保存、所有境界に従う不要mask整理、失敗時復元、YOLOとの独立性は本仕様を維持する。通常保存の個別確認条件は変更しない。

## 目的・対象

UIのDINO物体確認で今回採用したmaskだけを正式PNG保存し、実際にその保存先を上書きする場合だけ確認する。採用切替や既存バグで残った不要maskは、今回の対象画像の保存成功時に整理する。

対象はDINOの「保存して次へ」と、その保存・承認・公開参照の整合性である。既存の[手順](capture_workflow.md#承認用maskと上書き確認)と[公開契約](contracts/dino_mask_publication.md)を併せて参照する。

## 入出力

- 入力: 現行の画像・レビュー版、担当者、画像全体の確認、全候補の今回採否、器具UID＋個体番号の対応、確認済み推論mask、正式保存先の最新存在情報、必要な上書き同意。
- UIは既存の`GET /api/items`と`POST /api/complete-review`を使う。`decisions`、`assignments`、`overwrite_masks`など既存項目の形式を維持し、新APIやスキーマ変更を前提としない。
- 出力: 今回`accepted`の候補だけの正式PNG、対象画像の不要mask整理結果、確定採否・対応・承認、DINO承認用mask台帳・公開参照、採否・対応・承認の履歴。
- PNGは所属セッションの`masks/<画像stem>_<object_index（最小3桁）>.png`。元RGBと同寸法、8bitグレースケール、背景0／物体255、番号は詰めない。パス・hashは既存契約に従う。

## 動作

### 1. 保存対象の確定

- 今回の`accepted`候補だけを保存対象とする。`rejected`候補はPNGを新規作成しないが、候補・判定・監査履歴は保持する。
- 同一タグ（器具UID＋個体番号）の採用候補は最大1つ。未判定が残る保存は禁止する。全候補の判定、mask確認、担当者、現行性、器具対応など既存の検証は維持する。
- 全候補不採用でも採否を保存し、対象画像の不要maskを整理する。採用PNGは新規作成せず、DINO公開対象は0件。その他の画像承認条件やDINO専用承認／既存YOLO承認の扱いは変更しない。

### 2. 上書き確認

- UIは保存直前に存在情報を再取得する。UIで未保存の今回採否が`accepted`である候補について、同じレビュー版・`object_index`の最新`saved_mask_exists`を照合し、1件でも存在するときだけ確認する。
- 再取得した保存済み採否で今回のUI採否を置き換えない。候補の配列順ではなくindexで照合する。
- 不採用候補の保存先だけにファイルがある場合や、旧採用maskを削除するだけの場合は上書き確認しない。不要mask整理のための別の削除確認は追加しない。
- サーバーも今回採用する同じ保存対象の実ファイル有無を検証する。対象に既存ファイルがあれば`overwrite_masks: true`の明示同意なしに置換しない。UI再取得後にファイルが現れても未同意の置換はしない。
- No／Escapeでキャンセルした場合は保存せず同じ画像に留まり、ファイル・確定採否・承認状態を変更しない。未保存の今回選択を確定扱いにしない。

### 3. 不要maskの整理と所有境界

- 採用候補を切り替えて再保存したら、旧採用maskを削除し、今回の採用maskだけを残す（1タグ最大1mask）。
- バグで保存された不採用maskも、**今回の対象画像を再保存した時点**で整理する。起動時や別の一括処理では整理せず、他画像・他セッションへ処理を広げない。
- 削除できるのは対象画像が所有する承認用maskと安全に識別でき、今回の採用対象でないファイルだけ。画像stemやファイル名の前方一致だけで所有を推定しない。他画像の同名ファイル、推論原本、監査履歴は削除しない。別画像のファイルは上書き同意があっても置換しない。
- 所有の識別方法、過去レビュー版の参照や旧推論原本との共有の判別は後述の実装決定事項に従う。未確定の識別を前提に削除しない。

### 4. 台帳・公開参照・履歴

- `sam3_approved_masks`の現行ファイル参照と`sam3_dino_results`／`sam3_dino_objects`を、採用PNG保存・不要mask整理に整合させる。削除済みの承認用PNGを有効な現行ファイルとして参照・公開しない。
- 不採用候補の推論情報・採否行・採否イベント・対応変更イベント・レビュー／承認の監査履歴は保持する。履歴の保持は、過去に採用された承認用PNGを永久保持する意味ではない。
- 過去版の履歴に残るパス・hashは当時の記録であり、現在もファイルが存在する保証ではない。現行の承認用台帳・公開参照と区別する。既存の推論原本参照や`memory:`識別子を、正式PNGが現存する証拠として扱わない。
- DINO専用保存でYOLO矩形・YOLO承認ID／担当者／公開状態を変更しない。YOLO exportも再生成しない。

### 5. キャンセル・失敗

- 新規作成・置換・不要mask削除・採否／対応・承認・現行参照の更新を、保存成功時だけ一体として確定する。
- 通常の保存失敗およびSQL確定失敗時は、新規作成分を残さず、上書き・削除したファイルの元の内容と、採否・対応・承認・台帳・公開状態を変更前へ維持／復元する。失敗した操作だけの確定履歴を残さない。
- ファイル退避・復元は削除分も対象とし、SQL commit失敗も復元範囲に含む。プロセス強制終了に対するクラッシュ原子性など、既存以上の保証は追加しない。

## 受け入れ条件

| 条件・操作 | 期待結果 |
|---|---|
| 3候補から1候補採用し初回保存（既存PNGなし） | 採用1枚だけ保存。上書き確認なし |
| 今回採用maskの保存先に既存ファイルあり | 上書き確認あり。同意した場合だけ置換 |
| 不採用maskだけ既存 | 上書き確認なし。保存成功時に対象画像の不要maskを削除 |
| 採用候補を切り替えて再保存 | 新採用maskだけ残り、旧採用maskを削除。今回の採用先に既存ファイルがある場合だけ確認 |
| 全候補不採用 | 採用PNGを新規作成せず、対象画像の不要maskを整理。既存の画像承認条件は維持 |
| UI今回採否と保存済み採否が異なる／最新候補の並びが異なる | UIの今回採用候補と最新の同じindexで確認要否を判定 |
| UI再取得後、採用先にファイルが出現し上書き未同意 | サーバーが置換を拒否し、変更前を保持 |
| 上書きキャンセル／通常の保存失敗／SQL確定失敗 | 作成・置換・削除分を含むファイル、採否・対応・承認・台帳・公開状態が変更前のまま |
| 保存成功後の再読込・公開照合 | 採用maskのパス・hashが一致。不採用の履歴は残り、削除済みPNGを有効な現行参照として扱わない |
| 他画像・他セッション・同名画像が存在 | 他画像・他セッションのPNG、推論原本、既存監査履歴、YOLO矩形・承認状態を変更しない |
| 未判定あり／同一タグに複数採用 | 保存を拒否し、既存状態を変更しない |

## 実装決定事項

1. **所有識別**: 所属セッションDBの全レビュー版の`sam3_approved_masks`を`sam3_review_revisions`に結合し、解決済みパスごとの`session_id`＋`image_id`で所有を確定する。対象画像が所有するセッション直下`masks`のPNGだけを整理し、他画像も同じパスを所有する場合は同意の有無によらず停止する。
2. **所有不明・原本共有**: 現行／過去版の候補indexと記録済み画像stemから導出した完全一致の保存先に既存ファイルがあり、対象画像の台帳で所有を証明できなければ、保存全体を明示エラーで停止する。ファイル名だけでは削除・置換しない。それ以外の未登録ファイルは対象に含めない。推論原本mask、撮影RGB／深度、推論画像パスとの共有、または台帳がセッション`masks`外を指す場合も停止する。実データの手動修復・一括削除は行わない。
3. **旧版参照**: 保存時に対象画像の全版の承認用mask台帳行を同じトランザクションで外し、今回acceptedの現行版だけに新しいパス・hashを登録する。`refresh_handoff`により旧版／不採用候補のDINOスナップショットは既存の推論参照（`memory:`を含む）へ戻る。旧版は非公開のままで、採否・対応・レビューイベントおよび推論テーブルは保持する。スキーマ・HTTP APIの追加変更はない。

ファイル削除も既存の退避・復元処理に含め、後続SQL更新・公開同期・commitが失敗した場合は復元する。プロセス強制終了の追加保証はない。
